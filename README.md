# バス運行状況確認システム (Bus-Location-Checker) - v4.0

このシステムは、幼稚園や保育園、学校などのバス運行状況をリアルタイムで保護者に共有するためのツール群です。

## 🌟 アップデート情報

### v4.0 セキュリティ＆運用強化 : OK
- **Passkey (WebAuthn) 追加認証**: 管理者ログインに指紋や顔認証（パスキー）を導入。Google ログイン後の「Step-up MFA」として、VISA 3Dセキュア風の本人認証 gateway を実装。
- **メンテナンスモード**: `setting.txt` により、システム全体をメンテナンス画面に瞬時に切り替え。特定の日時指定による予約メンテナンスにも対応。
- **招待リンク限定登録**: ログイン画面からの自由な新規登録を制限。管理者から配布される「招待リンク（`?invite=...`）」経由でのみ登録が可能に。
- **管理者向け問い合わせシステム**: 管理者パネルからサービス事業者へ直接問い合わせが可能に。GAS 連携により、管理者の UID に基づくセキュアな認証を実装。
- **管理者権限の安定化**: Firestore Rules の最適化と詳細なエラーログ表示により、管理者ログイン時の「権限不足」エラーを解消。

### v1.0 製品版完成 : OK
- **初回登録・Google 連携フロー**: 利用情報を入力した後、Google アカウントで認証する「入力後ログイン」方式を採用。
- **マルチバス・兄弟対応**: 一つのアカウントに複数のバスを紐付け（別のバスを登録）、画面上部で簡単に切り替え可能に。
- **道路沿いの精緻なルート描画**: Leaflet Routing Machine と OSRM エンジンを利用し、地図上の道路を正確になぞるルートを表示。
- **10m 接近判定ロジック**: バス停の半径 10m 以内への進入で「到着」、脱出で「通過」と判定する厳格なロジックを実装。
- **リアルタイム時速・位置更新**: WebRTC P2P 通信により、遅延のない滑らかな位置・速度（km/h）表示を実現。
- **管理者機能のフルセット**: 停留所へのクイックジャンプ、路線の完全削除、全登録データに基づく動的な年度フィルタリング、バス停の並べ替え機能。
- **詳細設定モード**: 各バスごとに「道路への吸着（スナップ）」の ON/OFF や、運行停止状態の切り替えが可能に。
- **セキュリティの強化**: 管理者ポータルをパスコードで保護し、SHA-256 ハッシュ照合を採用。

## ⚙️ 運用設定 (setting.txt)

リポジトリルートの `setting.txt` を編集することで、システムの稼働状態を制御できます。

### 設定方法
- **通常稼働**: `false`
- **即時メンテナンス**: `true`
- **予約メンテナンス**: `true 開始日時~終了時間`
  - 形式: `true YYYY/MM/DD/HH:mm~HH:mm`
  - 例: `true 2026/06/06/09:00~13:00` (2026年6月6日の9時から13時まで)

## 🔒 セキュリティと認証

### 管理者ポータル
- **アクセス**: ルートの `index.html` からアクセス。
- **パスコード**: `admin-dev-7x9q` (README にのみ記載)
- **二要素認証 (MFA)**: 初回ログイン時はパスキーなしで入れますが、管理画面の「システム設定」からパスキーを登録すると、次回以降 Google ログインの後にパスキー認証（パソコン大魔王グループセキュリティサービス）が必須となります。

### ユーザー認証
- **Google アカウント連携**: 名前、クラス名、招待コードを入力した後に Google ログインすることで、データが永続的にアカウントに紐付けられます。
- **データの永続化**: 「自分のバス停」設定などは Firestore の `users_meta` に保存され、機種変更後も引き継がれます。

## 📖 詳細仕様とロジック

### バスの状態表示（時間外 / 停止中）
1. **通信断絶判定**: バス側からの位置信号が **6分以上** 途絶えると「時間外 / 停止中」の赤いバッジが表示されます。
2. **ルート描画の減衰**: 通信断絶時はルートの線が薄くなり、情報の鮮度が低いことを示します。

### 10m 接近・通過判定の仕組み
- **進入 (Arrived)**: バスがバス停の座標から半径 **10m 以内** に入った瞬間に「到着」と判定し、マーカーの色を更新します。
- **脱出 (Passed)**: 到着判定後、バスが再び半径 **10m の外側** に出た瞬間に「通過済み」となり、ルートの線とマーカーがグレーアウトします。
- **補完ロジック**: GPS の瞬き等で 10m 判定を逃した場合でも、OSRM の詳細ルート上のインデックスを監視し、バス停を一定以上通り過ぎた場合に自動的に「通過済み」に切り替えます。

### エンドツーエンド暗号化 (E2EE) の詳細仕様
本システムでは、位置情報や利用者名などの機密データを保護するため、高度な暗号化を実装しています。

1.  **暗号化アルゴリズム**: AES-256-CBC (Cipher Block Chaining) を採用しています。
2.  **クライアントサイド処理**: すべてのデータは、デバイスから送信される**前**に JavaScript (CryptoJS) を使用して暗号化されます。サーバー（Firestore）には暗号化された文字列のみが保存され、Firebase 側でも内容は一切解読できません。
3.  **初期化ベクトル (IV)**: 暗号化ごとに 16バイトのランダムな IV を生成し、`IV:暗号文` の形式で保存します。これにより、同じ位置情報でも毎回異なる暗号文が生成されます。
4.  **鍵の配布仕組み**:
    *   管理者がバス路線を作成した際、256ビットの秘密鍵が自動生成されます。
    *   招待コードは `busId:secretKey` を Base64 エンコードしたものです。
    *   利用者はこの招待コードを入力することで、自身の端末内にのみ秘密鍵を保持し、データの復号が可能になります。

### 管理者向け問い合わせ・ユーザー削除システム (GAS)
管理者がユーザーを削除したり、サポートへ問い合わせたりする機能は、Google Apps Script (GAS) 経由で実行されます。
※ 各 GAS の Web App URL は管理者画面の `GAS_USER_MGMT_URL` および `GAS_INQUIRY_URL` に設定する必要があります。

#### GAS セットアップ手順:
1. Google Apps Script エディタを開き、`gas/user-management.gs` および `gas/inquiry.gs` の内容をそれぞれ別プロジェクトとして貼り付けます。
2. GCP コンソールでサービスアカウントを作成し、`Firebase Authentication 管理者` のロールを付与します。
3. JSON キーを作成し、そのメールアドレスと秘密鍵をスクリプト内の `CLIENT_EMAIL` と `PRIVATE_KEY` に記入します。
4. スクリプト内の `ALLOWED_DOMAIN` に、管理者ページを公開するドメイン（例: `https://your-name.github.io`）を設定します。
5. 「デプロイ > 新しいデプロイ」を選択し、種類を「ウェブアプリ」、アクセスできるユーザーを「全員」にしてデプロイします。
6. 発行された URL を `web/admin/index.html` の `GAS_WEB_APP_URL` に設定します。
